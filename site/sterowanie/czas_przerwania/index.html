    Ćwiczenie 6 i 7 – Czas i Przerwania (millis, ISR)

    Potrzebujesz: 🔌 Układ ESP32-C6, Dioda LED, Rezystor, Przycisk na breadboardzie.

    Do tej pory używałeś funkcji delay(). Wydaje się wygodna, ale ma fatalną wadę – to tzw. funkcja blokująca. Gdy wywołujesz delay(1000), procesor dosłownie odlicza "w głowie" od zera do tysiąca, całkowicie zamrażając swoje działania. Nie jest w stanie w tym czasie sprawdzić przycisku, nie jest w stanie obsłużyć odbierania sygnału alarmowego z sieci Wi-Fi. Gdybyś budował grę na komputer z użyciem delay(), po animacji ciosu mieczem cała gra na sekundę przestałaby reagować na myszkę i klawiaturę!

    W tym dziale naprawimy ten problem na dwa sposoby: używając systemowego zegara millis() oraz wykorzystując Przerwania Zewnętrzne (ISR) do natychmiastowej reakcji sprzętowej.

    Ćwiczenie 6 – Koniec z zamrażaniem. Zegar millis()

    Zamiast zatrzymywać procesor by odczekać sekundę na zapalenie diody, każemy mu działać swobodnie w pętli bez końca, i na każdej iteracji niech zerkie na zegarek. Funkcja millis() zwraca ilość milisekund, jaka upłynęła od samego włączenia zasilania układu ESP32.

    Zasada działania przypomina robienie herbaty: - Zamiast (delay): Włączasz czajnik i gapisz się w niego 5 minut całkowicie ignorując szczekającego psa. - Używając millis: Zapisujesz godzinę 12:00. Idziesz się bawić z psem (loop). Co jakiś czas patrzysz na zegarek – czy jest już 12:05? Jeśli nie, bawisz się dalej. Jeśli tak – wyłączasz czajnik!

    Kod: Blink bez delay()

    Poniższy kod sprawia, że dioda mruga co pół sekundy, a procesor może jednocześnie wykonywać tysiące innych operacji "w tle" pętli loop bez najmniejszego zająknięcia!

    const int PIN_LED = 2;

// Ponieważ millis rośnie bez końca, nie zmieści się w int po ~30 sekundach. 
// Używamy typu zmiennej "unsigned long" (bez znaku minus, długa), która pomieści aż 49 dni pracy układu.
unsigned long zapisany_czas = 0; 
const unsigned long interwal = 500; // czas do odczekania: 500 ms (pół sekundy)
int stan_diody = LOW;

void setup() {
  pinMode(PIN_LED, OUTPUT);
}

void loop() {
  // Sprawdzamy, która godzina jest na systemowym stoperze W TYM MOMENCIE
  unsigned long obecny_czas = millis();

  // Sprawdzamy różnicę czasu z zegarka w porównaniu do czasu zapisanego w notatniku 
  if (obecny_czas - zapisany_czas >= interwal) {

    // Zapisujemy nową godzinę startową w notatniku do odmierzania
    zapisany_czas = obecny_czas;

    // Tu robimy nasz kod mrugania:
    if (stan_diody == LOW) {
      stan_diody = HIGH;
    } else {
      stan_diody = LOW;
    }
    digitalWrite(PIN_LED, stan_diody);
  }

  // W tym miejscu loop obraca się w nieskończoność bez milisekundy pazu. 
  // Możesz tu badać stan przycisku i nigdy nie "przegapisz" wciśnięcia!
}

    Ćwiczenie 7 – Przerwania (ISR), czyli Pociąganie za Ramię

    W Module 3 (Podstawy) sprawdzaliśmy w pętli "Czy ktoś kliknął? Czy ktoś kliknął?". Nazywa się to potocznie polling. To mało efektywne i męczy układ. Przerwanie (Interrupt) zmienia paradygmat. Konfigurujesz port (np. numer 9 z przyciskiem) i dajesz mu sprzętowy mechanizm reagowania na skoki napięcia. Kiedy nastąpi skok uderzenia w przycisk, procesor ułamku milisekundy "upuszcza" wszystkie dotychczasowe obliczenia w kodzie, teleportuje się prosto do zdefiniowanej w cieniu specjalnej i małej funkcji obsługującej skok, natychmiast ją realizuje, i jak gdyby nigdy nic wraca dokładnie w to samo miejsce kodu głównego!

    Jak zdefiniować przerwanie?

    Rejestrujemy je na dany pin, wybieramy jaka funkcja w naszym kodzie ma się aktywować po usłyszeniu i określamy na jaki skok prądu ma uważać. - RISING – zbocze narastające (napięcie idzie do góry, LOW → HIGH) - FALLING – zbocze opadające (HIGH → LOW - to nas obchodzi dla PULLUP) 

    attachInterrupt(digitalPinToInterrupt(PIN), funkcja_ktora_zbudujemy, FALLING);

    ZASADY PRZERWAŃ!

    Funkcja uruchamiana przez skok (tzw. Interrupt Service Routine - ISR) na ESP32 musi mieć przedrostek IRAM_ATTR by została na stałe umieszczona w szybkiej pamięci! Ponadto, musi być ekstremalnie szybka. Nie wolno w niej wypisywać Serial.println(), używać delay(). Powinna jedynie zmieniać stan małej liczby czy "flagi" bool. Dodatkowo zmienne, które modyfikujemy w przerwaniach, a które czytamy w loop(), by były poprawnie przeliczane przez procesor, muszą mieć w deklarecji dopisek volatile.

    Kod: Wyręczenie Pętli przez Sprzęt

    Poniższy program inkrementuje licznik wciskając przycisk tak szybko, jak to tylko fizycznie możliwe, bez używania instrukcji "if digitalRead".

    const int PIN_BTN = 9;

// To flaga widoczna globalnie, dlatego posiada "volatile"
volatile int licznikKlikniec = 0;
volatile bool flaga_zmiany = false;

// NASZA UKRYTA FUNKCJA PRZERWANIA ISR
void IRAM_ATTR moje_przerwanie_przycisku() {
  licznikKlikniec++;
  flaga_zmiany = true; // Flaga dająca sygnał pętli głównej: "Hej stary, wciśnięto przycisk!"
}

void setup() {
  Serial.begin(115200);
  pinMode(PIN_BTN, INPUT_PULLUP);

  // Zarejestruj przerwanie na nóżce 9, jeśli prąd spadnie (FALLING) - uderz w moje_przerwanie_przycisku.
  attachInterrupt(digitalPinToInterrupt(PIN_BTN), moje_przerwanie_przycisku, FALLING);

  Serial.println("System gotowy. Wcisnij przycisk!");
}

void loop() {
  // Procesor może udawać, że zajmuje się trudnymi obliczeniami:
  delay(500); // Użyjemy delay tylko w formie demonstracji, że Interrupt działa POMIMO delay!

  // Sprawdzamy czy nasza flaga z Interruptu zapłonęła:
  if (flaga_zmiany == true) {
      flaga_zmiany = false; // Resetujemy sygnał
      Serial.print("Niezależny sprzetowy licznik odbil klikniecie o wartosci: ");
      Serial.println(licznikKlikniec);
  }
}

    Zadanie: Debouncing przerwaniem

    Kiedy testowałeś kod, pewnie widziałeś że licznik za sprawą jednego kliknięcia podbił się o np. 4 uderzenia w Monitorze. Wróciło słynne "drganie styków". ISR zareagował na to w mikrosekundzie z pełną wiernością fali wpadającej po krzywym plastiku w blaszkę!

    Zmodyfikuj kod powyżej. Wykorzystaj wiedzę z Ćwiczenia 6. Dodaj zmienną czasową unsigned long ostatnie_odbicie i użyj funkcji millis() BEZPOŚREDNIO w obiekcie ISR! Jeśli od czasu ostatniego naciśnięcia do obecnego czasu z stopera nie minęło np. chociaż 100 ms, to znaczy że było to po prostu chamskie plastikowe drgnięcie odbijającej blaszki i ISR ma zignorować inkrementację! Tylko wtedy licznik naliczy 1 perfekcyjne kliknięcie per wcisk!

    Pokaż rozwiązanie 
    const int PIN_BTN = 9;

volatile int licznikKlikniec = 0;
volatile bool flaga_zmiany = false;
volatile unsigned long ostatnie_odbicie = 0; // Musi byc volatile bo bedzie obrabiane w ISR

void IRAM_ATTR moje_przerwanie_przycisku() {
  // Zgrywamy z zegara systemowego kiedy nas tu wrzuciło:
  unsigned long teraz = millis();

  // Jesli od ostatniego razu minelo MNIEJ jak np. 50 milisekund to to zwykle drganie, nic nie robimy:
  if (teraz - ostatnie_odbicie > 50) {
      licznikKlikniec++;
      flaga_zmiany = true;
  }
  ostatnie_odbicie = teraz;
}

void setup() {
  Serial.begin(115200);
  pinMode(PIN_BTN, INPUT_PULLUP);
  attachInterrupt(digitalPinToInterrupt(PIN_BTN), moje_przerwanie_przycisku, FALLING);
}

void loop() {
  if (flaga_zmiany == true) {
      flaga_zmiany = false;
      Serial.println(licznikKlikniec);
  }
}
