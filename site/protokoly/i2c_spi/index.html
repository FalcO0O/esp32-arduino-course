    Magistrale cyfrowe: I2C oraz SPI

    Potrzebujesz: 🔌 Moduł Akcelerometru MPU6050, Wyświetlacz OLED SSD1306 SPI, Breadboard, przewody jumper.

    W poprzednim ćwiczeniu z UART widzieliśmy komunikację najprostszą z możliwych: jeden nadawca, jeden odbiorca. Gdy podłączamy skomplikowane czujniki (np. pogodowe) czy wyświetlacze, używamy prawdziwych magistrali (bus). Magistrala to system drutów, do którego możemy wpinać mnóstwo różnych urządzeń naraz, zupełnie tak jak wpina się do komputera myszkę, klawiaturę i drukarkę przez to samo wejście USB.

    W świecie mikrokontrolerów królują dwa protokoły: powolny lecz genialnie zorganizowany I2C, oraz szaleńczo szybki, ale kable-żerny SPI.

    Ćwiczenie 9 – I2C i MPU6050

    I2C (Inter-Integrated Circuit) to magistrala wymagająca tylko 2 przewodów od komunikacji. Jest genialna na płytce, gdzie mamy deficyt pinów. - SDA (Serial Data) – tym drutem lecą dane. - SCL (Serial Clock) – tym drutem idzie sygnał tykającego zegara nadający tempo.

    Jak procesor odróżnia do kogo mówi?

    Na I2C panuje kultura. Główny procesor (Master) jest szefem. Otwiera gębę i mówi "Urządzenie numer 68, podaj temperaturę!". Każdy podpięty czujnik milczy, za wyjątkiem czujnika z przypisanym adresem nr 68, który mu odkrzykuje na tej samej linii.

    🎯 [Otwórz Wokwi z układem MPU6050] (link zostanie zaktualizowany)

    Użyjemy modułu z czujnikiem przeciążeń MPU6050, aby badać np. jego pochylenie względem ziemi.

    Podłączenie

    MPU6050    ESP32-C6 DevKit
────────────────────────────
VCC   ──── 3V3  (PAMIĘTAJ: 3.3V, a nie 5V!)
GND   ──── GND
SDA   ──── GPIO6
SCL   ──── GPIO7

    Ciekawostka o bibliotekach

    Skomplikowane moduły komunikacyjne wysyłają do mikrokontrolera surowe, trudne do analizy bajty kalibracyjne. Dlatego by je w ogóle uruchomić, używamy bibliotek napisanych przez inżynierów. W Arduino IDE musisz pobrać do tego projektu bibliotekę MPU6050_light.

    Kod z wykorzystaniem gotowej biblioteki

    #include <Wire.h> // biblioteka zarządzająca liniami I2C w Arduino
#include <MPU6050_light.h> // biblioteka zarządzająca samym czujnikiem

const int I2C_SDA = 6;
const int I2C_SCL = 7;

MPU6050 mpu(Wire);

void setup() {
  Serial.begin(115200);

  // Mówimy sprzętowi I2C gdzie ma nogi
  Wire.begin(I2C_SDA, I2C_SCL);

  Serial.println("Szukam MPU6050 na drucie...");
  byte status = mpu.begin();

  if (status != 0) {
    Serial.println("Nie moglem sie z nim dogadać. Czy ma prad?");
    while (1); 
  }

  Serial.println("Nie ruszaj układem – kalibruję...");
  delay(1000);
  mpu.calcOffsets(); 
  Serial.println("Kalibracja zakończona!");
}

void loop() {
  mpu.update(); // MPU, podaj nowe paczki danych z I2C!

  Serial.print("Kąt X: ");
  Serial.print(mpu.getAngleX());
  Serial.print("°\tKąt Y: ");
  Serial.println(mpu.getAngleY());

  delay(100);
}

    Zadanie: Wykrywacz wstrząsów

    Podłącz układ, wgraj kod i sprawdź w Serial Plotterze jak reaguje na obracanie! Następnie zmodyfikuj kod. Zamiast korzystać z .getAngle, użyj udostępnionej w bibliotece formy .getAccX() by pozyskać akcelerację osi. Spraw by procesor zareagował czerwoną diodą na przeciążenie przekraczające na tej osi pułap 2G (standardowa grawitacja dla bezruchu to zawsze z definicji 1G, uderzenie/wstrząśnięcie modułem ją podbija).

    Pokaż rozwiązanie zadania 
    #include <Wire.h>
#include <MPU6050_light.h>

const int I2C_SDA = 6;
const int I2C_SCL = 7;
const int PIN_LED = 2; // Obojetnie jaki pin na diode

MPU6050 mpu(Wire);

void setup() {
  Serial.begin(115200);
  pinMode(PIN_LED, OUTPUT);
  Wire.begin(I2C_SDA, I2C_SCL);
  mpu.begin();
  delay(1000);
  mpu.calcOffsets(); 
}

void loop() {
  mpu.update(); 

  // Pobranie przeciążenia:
  float przeciazenieX = mpu.getAccX();

  // Jesli przekroczymy 2.0 (czyli zjawisko uderzenia):
  // z racji na to ze mozna szarpnac w tył, bierzemy tez wartosci minusowe
  if (przeciazenieX > 2.0 || przeciazenieX < -2.0) {
      digitalWrite(PIN_LED, HIGH);
      Serial.println("WSTRZĄS WYKRYTY!");
  }

  delay(10);
}

    Ćwiczenie 10 – SPI i Ekran Graficzny

    I2C jest wspaniały, ale ma wąskie gardło z racji tylko jednej linii wymiany danych. Gdy potrzebujemy wysłać obraz, czyli całe matryce z dziesiątkami tysięcy pikseli, I2C będzie miało uciążliwego "laga". SPI (Serial Peripheral Interface) to protokół na sterydach. Cierpi z racji pożerania aż 4 kabli sygnałowych na samo nawiązanie gadki, ale z racji posiadania dedykowanych żył na Słuchanie i Gadanie, prędkości są liczone w megabajtach.

    Piny magistrali

    • SCK – Zegar synchronizacyjny.
    • MOSI – Kanał wyjściowy (z Mastera do Urządzenia).
    • MISO – Kanał wejściowy (z Urządzenia do Mastera).
    • CS (Chip Select) – "Zarządca drutu". Tutaj zamiast pytać o adres tak jak w I2C, mikrokontroler sztywnym dedykowanym kablem fizycznie "pobudza" prądem układ mówiąc "Ty teraz słuchasz!". Każde kolejne urządzenie SPI na magistrali pochłania więc kolejny odrębny dla procesora przewód CS.

    Podłączenie ekranu OLED

    Użyjemy popularnego SSD1306. Z racji, że to on nas słucha (wyświetla co mu każemy, a nie na odwrót), zignorujemy linię MISO (odbiorczą) bo ekran nie ma nam nic konstruktywnego do odesłania. Wyświetlacz żąda za to innych kabli sterujących jak RES (sygnał do restartu jego bebechów) i DC (wskaźnik czy po MOSI leci pixel do pomalowania, czy leci np. komenda ściemniania ekranu).

    SSD1306 (SPI)   ESP32-C6
──────────────────────────────
VCC   ────────  3V3
GND   ────────  GND
SCK   ────────  GPIO6   
SDA/MOSI ─────  GPIO7  
RES   ────────  GPIO4  
DC    ────────  GPIO3   
CS    ────────  GPIO2

    Wymagane z menedżera bibliotek: Adafruit SSD1306, Adafruit GFX Library.

    Kod obsługujący wysyłanie grafiki

    Biblioteka tworzy dla nas bufor wirtualnego obrazu, a my na koniec prosimy procedurę by potężnym szarpnięciem wyrzuciła całą tę bitmape po SPI na wyświetlacz.

    #include <SPI.h>
#include <Adafruit_GFX.h>
#include <Adafruit_SSD1306.h>

#define OLED_SCK  6
#define OLED_MOSI 7
#define OLED_RES  4
#define OLED_DC   3
#define OLED_CS   2

// Konfigurujemy ekran 128 na 64 pixeli i podajemy mu przypisanie pinów SPI
Adafruit_SSD1306 display(128, 64, OLED_MOSI, OLED_SCK, OLED_DC, OLED_RES, OLED_CS);

void setup() {
  Serial.begin(115200);

  // Uruchomienie ekranu
  if (!display.begin(SSD1306_SWITCHCAPVCC)) {
    Serial.println("SSD1306 padl martwy.");
    while (1);
  }

  // Wyczyść ewentualne logo Adarfruit:
  display.clearDisplay();

  // Piszemy po wirtualnej kartce:
  display.setTextSize(2);              // Rozmiar duzy
  display.setTextColor(SSD1306_WHITE);
  display.setCursor(0, 0);            // Wspolrzedne XY (lewy gorny rog to 0, 0)
  display.println("ESP32-C6");

  display.setTextSize(1);              // Zmiana rozmiaru w trakcie
  display.println("Kurs Arduino SPI");

  // Najwazniejsza funkcja – zrzuć ten ułożony projekt przez rurę SPI na szklany ekran!
  display.display();                   
}

void loop() {
   // Mozemy robic cokolwiek, np rysowac pasek:
   static int klatki = 0;
   klatki++;

   display.clearDisplay();
   // Rysowanie wypelnionego prostokata (Ograniczamy klatki zeby nie wyjsc za bok 128px):
   display.fillRect(0, 32, (klatki % 128), 10, SSD1306_WHITE); 
   display.display();
}

    Zadanie: Integracja Projektów!

    Weź kod z ekranu graficznego i kod z MPU6050 (wymagają zupełnie innej klasy magistral, więc będą idealne na "łączenie" ich na odrębnych portach!). Skonfiguruj ekran i czytaj z MPU6050, by na bieżąco, na białym tle wyświetlacza OLED rzucać co sto milisekund aktualny i płynny odczyt z akcelerometru na żywo!

    🏆 Podsumowanie Protokołów Szeregowych

    Teraz widzisz dlaczego sprzęt komputerowy dzieli się na tyle typów wejść.

    Cecha I2C (Akcelerometry) UART (Przewody Loop) SPI (Wyświetlacze)
    Liczba potrzebnych przewodów sygnałowych Tylko 2 (SDA, SCL) 2 (TX, RX) Aż 4+ (MOSI, MISO, SCK, CS)
    Ilość dozwolonych urządzeń naraz na kablach Nawet ok. 120 (po adresach numerycznych) Tylko 2 (kabel punkt-punkt) Wiele (ale każde kolejne urządzenie zabiera z ESP kolejny pin CS!)
    Prędkość komunikacji Dosyć wolna (~400 kbps) Średnia Bardzo Szybka (nawet kilkadziesiąt mbps)
    Użyteczność Najlepsza do malutkich czujników wewnątrz robota. Najlepsza do połączeń długim kablem z komputerem by wysłać text. Zarezerwowana do rzeczy bardzo ciężkich cyfrowo jak Karty SD czy Ekran Graficzny.

    (Oczywiście świat elektroniki jest znacznie większy. Do aut w celu omijania zakłóceń prądu wymyślono sieć magistrali CAN. Do zaawansowanego sprzętu audio używa się magistrali I2S z kanałami L/R... Ale te trzy z naszego kursu pokryją na razie 95% Twoich mikrokontrolerowych potrzeb!)
